AptiRise 1.1.2 (13) - production ad integration corrections
Based on your uploaded AptiReady(5).zip

This is the complete source project, with generated build outputs/caches removed.
No source merging, test-device registration, demo flags or extra diagnostics are required to use this copy.

1. Extract this project to a new folder, keeping your existing project as a backup.
2. On your Windows development computer, open AptiReady and run BUILD-RELEASE.bat.
   Or open the folder in Android Studio, sync it, and build a signed release.
3. The build creates:
   APK: app/build/outputs/apk/release/app-release.apk
   Play bundle: app/build/outputs/bundle/release/app-release.aab

Release uses your existing real AdMob App ID and four production ad unit IDs.
Debug continues to use Google's demo units. The prior useGoogleDemoAds override and hardcoded test-device registration have been removed from app code.
Version is increased to 1.1.2 / 13 so it can update your prior 1.1.1 / 12 build, subject to the same signing identity.
The original signing files and Firebase configuration are preserved. An APK must use the same signing identity as the installed app to update it; Play-installed apps may use a different Play App Signing key.

WHAT WAS FIXED
- A failed native request now receives bounded retries while its screen remains visible; the previous backoff timestamp had no timer to trigger another request.
- Returning to a native placement reuses a valid cached ad instead of destroying it immediately. Expired ads are discarded.
- Banner state updates do not hide an already loaded banner. The wrapper owns one layout listener and cleans up replaced/destroyed views.
- Failed banners retry with increasing delays; retries pause when the screen pauses, and cancel when destroyed. Initial attempt plus at most three retries; invalid requests do not retry.
- Result pages retry failed interstitial preloads while visible, using the same bounded backoff. Ads remain restricted to the existing result-exit action and frequency rules. Navigation is not delayed to wait for an ad.
- A failure to save full-screen frequency policy blocks automatic full-screen ads without globally disabling unrelated native, banner and rewarded ads.
- Rewarded and interstitial failures include full error details in logs. A rewarded ad still requires an explicit user action and verified reward callback.
- Theme changes are dispatched to the main thread while content initialization stays off the UI thread.

WHAT THIS DOES NOT ESTABLISH
Your previous native, banner and interstitial production-unit requests returned SDK error 3 / No fill. You reported that Google demo ads work in the release diagnostic build. These observations suggest production-serving configuration/inventory needs investigation, but do not identify a specific hidden account restriction.
This package fixes source-visible integration defects. It does not force Google to return a live ad, resolve AdMob account decisions, or guarantee fill on every request. Missing European consent forms were reported in your earlier logs, but those same runs had canRequestAds=true and requestsReady=true. The code keeps UMP consent checks; it does not bypass them by country.
